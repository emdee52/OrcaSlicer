- Fork: `OrcaFS-NeotkoCM` @ `3bd92365d0` (2.4.7). Base for this diff: Snapmaker `v2.4.0`.
- Category: B. Status: **ported** - build clean, `ctest` 2407/2407, visual check pending.
- Marker: `[ORCAPORT:SU-18]`.

## What it is

What needs holding faces the bed, so from above it is hidden - the release note's surfboard case
meant turning the view constantly to paint along an edge. A third glyph button in the view strip puts
the camera under the part, i.e. the stock Bottom view (`GLCanvas3D::select_view("bottom")`).

Not a latched state: the button is drawn off and is a one-shot action, exactly like the fork's.

## Anchors

One file: `src/slic3r/GUI/Gizmos/GLGizmoSupportZones.cpp`, `render_view_strip()`. No config key, no
slicing change, no new symbol beyond the marker.

- `Glyph::Landing` already exists in this file's `enum class Glyph`, so no icon work.
- `Camera::select_view` accepts `"bottom"` (verified against its direction list).

## Note on localization

The fork builds its tooltip from concatenated `_u8L` fragments. `OrcaSlicer/AGENTS.md` forbids
assembling a message from translated pieces, so the string here is **one complete msgid**. The two
pre-existing strings above it (Highlight overhangs, Show what still needs holding) still use the
fork's concatenation - left as found, not part of this feature.

Build clean + `ctest` 2407/2407. Visual: click it and the camera goes to the bottom view. Nothing
