# SU-17 - Support Zones: the overhang-only brush

- Source: `NEOTKOCM_RELEASE_2_47.md` ("Overhang only (new, on by default)").
- Fork: `OrcaFS-NeotkoCM` @ `3bd92365d0` (2.4.7). Base for this diff: Snapmaker `v2.4.0`.
- Category: B. Status: **ported** - build clean, `ctest` 2407/2407, visual check pending.
- Marker: `[ORCAPORT:SU-17]`.

## The problem

The brush swept everything inside its circle: the underside, the edge and a bit of the top. On the
release note's surfboard only a third of what was painted was real overhang, and painting along the
edge made the zone grow to the top of the board.

## The fix

With the filter on, a facet is only **marked** when it leans past the overhang angle; the flood-fill
still **walks** through unfiltered facets, because a wall carries the stroke from one bulge to the
next and cutting the walk would break the stroke. So `filter`/`leans_enough(f)` gate the marking
only, not the traversal. The eraser never filters - whatever is marked has to be removable.

Two design points worth keeping:

- **The threshold is frozen into the gesture** (`ZoneGesture::overhang_cut_deg`, JSON `"oc"`), not
  read live. A zone painted at 30 deg must repaint the same faces after the user moves the global
  overhang angle; otherwise reopening an old zone silently repaints it.
- **It follows the live slider while it is being moved.** The "Highlight overhangs" slider, when
  moved with the filter on and stamps present, writes `m_paint_cut_deg = m_overhang_threshold_deg`
  and repaints the stroke, so the user sees how much the brush grabs before creating the zone.

## Compatibility (the important part)

- `"oo"`/`"oc"` are written **only when the filter is on**, so a gesture painted without it produces
  the same JSON as before.
- Both are read with defaults (`false` / 30), so a pre-SU-17 gesture repaints exactly as stored.
- `end_edit()` resets the next zone to the default, so creating a zone after editing an old
  filter-less one does not inherit `false`.
- The filter is only stored for the brush footprint (`block_tree_mode()`), matching the fork: only
  that footprint paints facets.
